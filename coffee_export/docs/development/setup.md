# Development Setup

## Prerequisites

- **Python 3.11+** (3.12 recommended)
- **Git**
- **Make** (optional, for convenience commands)

## Initial Setup

```bash
# 1. Clone the repo
git clone <repo-url> coffee_export
cd coffee_export

# 2. Create virtual environment
python3 -m venv venv
source venv/bin/activate    # Linux/macOS
# venv\Scripts\activate     # Windows

# 3. Install dependencies
pip install -r requirements.txt

# 4. Configure environment
cp .env.example .env
# Edit .env as needed (defaults work for local development)

# 5. Install pre-commit hooks
pre-commit install

# 6. Verify setup
python scripts/verify_setup.py
# Expected: ✓ All checks passed — Step 0 complete!
```

## Daily Workflow

```bash
# Activate venv (every new terminal)
source venv/bin/activate

# Run the dashboard
streamlit run coffee_export/dashboard/app.py

# Run a specific agent
python -m coffee_export.agents.agent1 kpi

# Run tests
pytest

# Create a database migration (after changing SQLAlchemy models)
alembic revision --autogenerate -m "add new table"
alembic upgrade head

# Format + lint (also runs automatically on commit via pre-commit)
black .
ruff check . --fix
```

## Code Quality Tools

### Black (formatter)

Auto-formats Python code. Configuration in `pyproject.toml`.

```bash
# Format all files
black .

# Check without modifying (CI mode)
black --check .

# Format a single file
black coffee_export/config.py
```

### Ruff (linter)

Fast linter that replaces flake8, isort, and pyupgrade. Configuration in `pyproject.toml`.

```bash
# Lint all files (with autofix)
ruff check . --fix

# Lint without fixing (CI mode)
ruff check .

# Lint a single file
ruff check coffee_export/config.py
```

### Pre-commit

Runs black, ruff, and file checks before every commit. Configuration in `.pre-commit-config.yaml`.

```bash
# Install hooks (run once after clone)
pre-commit install

# Run manually on all files
pre-commit run --all-files

# Update hook versions
pre-commit autoupdate
```

**If a commit is blocked by pre-commit:**
1. The hooks auto-fix what they can (black formatting, ruff autofix, trailing whitespace).
2. Stage the fixed files: `git add -A`
3. Commit again: `git commit -m "your message"`
4. Repeat until all hooks pass.

## Database Migrations (Alembic)

```bash
# Show current migration
alembic current

# Show migration history
alembic history

# Apply all pending migrations
alembic upgrade head

# Roll back one migration
alembic downgrade -1

# Roll back to a specific migration
alembic downgrade <revision_id>

# Create a new migration (after changing SQLAlchemy models)
alembic revision --autogenerate -m "description of change"

# Generate SQL without applying (for review)
alembic upgrade head --sql
```

**Migration rules:**
1. Never edit a migration that's been committed and applied to production.
2. Always test both `upgrade` and `downgrade` locally.
3. One logical change per migration.
4. Review autogenerated migrations before committing — they can miss constraints.

## Logging

Logs go to two places:
- **Console** (Rich, colored) — for development
- **File** (`data/logs/coffee_export.log`, rotating 10MB × 5) — for analysis

```python
from coffee_export.utils.logging import setup_logging, get_logger

setup_logging()  # call once at app startup
log = get_logger(__name__)
log.info("Server started", extra={"port": 8501})
```

Log level is controlled by `APP_LOG_LEVEL` in `.env` (`DEBUG` / `INFO` / `WARNING` / `ERROR` / `CRITICAL`).

## Environment Variables

See `.env.example` for all options. Key settings:

| Variable | Default | Description |
|----------|---------|-------------|
| `APP_ENV` | `development` | `development` / `staging` / `production` |
| `DATABASE_URL` | `sqlite:///data/coffee_export.db` | Database connection (swap for `postgresql://...` in prod) |
| `APP_TIMEZONE` | `Africa/Addis_Ababa` | All timestamps use this TZ |
| `APP_LOG_LEVEL` | `INFO` | Log level |
| `SAMPLE_BUDGET_FULL_SETS` | `3` | Max Type A sample sets per week |
| `DASHBOARD_PORT` | `8501` | Streamlit port |

**Never commit `.env`** — it's in `.gitignore`. Each environment (dev, staging, prod) has its own `.env`.

## Troubleshooting

### "ModuleNotFoundError: No module named 'coffee_export'"

You forgot to activate the venv, or the project root isn't on `sys.path`.

```bash
source venv/bin/activate
# Or set PYTHONPATH:
export PYTHONPATH=/path/to/coffee_export:$PYTHONPATH
```

### "pre-commit: command not found"

Pre-commit isn't installed in your active venv.

```bash
pip install pre-commit
pre-commit install
```

### "alembic: command not found"

Same — install in venv.

```bash
pip install alembic
```

### Database is locked

Another process is using the SQLite database. SQLite allows one writer at a time.

```bash
# Find and kill the other process
lsof data/coffee_export.db
# Or just restart your terminal / IDE
```

WAL mode is enabled by default, which allows concurrent readers. Only writers block each other.

### Pre-commit keeps failing on the same file

The file might have an issue black/ruff can't auto-fix (e.g., unused variable that's actually a bug).

```bash
# Run ruff with verbose output to see what's wrong
ruff check path/to/file.py --verbose

# Temporarily skip hooks for a commit (NOT recommended)
git commit --no-verify -m "emergency fix"
```
